# Team Rules and Collaboration Guide

## 1. Branch Strategy (Git Flow Strategy)
- `main`: Stable production version.
- `develop`: Main integration branch.
- Conventions: `feature/`, `fix/`, `docs/`, `refactor/`, `test/`.

## 2. Commit Convention (Conventional Commits)
Follow the format `<type>: <description>`.

## 3. Pull Request (PR) and Code Review Workflow
- Review by at least 1 teammate is mandatory before merging.
- *Squash and Merge* is recommended.

## 4. Quality Standards
- Strict use of `.gitignore` for credentials and environment variables (`.env`).
- Remove debugging code before submitting a PR.

## 5. Task Management
- Use **GitHub Issues** and **GitHub Projects** to track work.
